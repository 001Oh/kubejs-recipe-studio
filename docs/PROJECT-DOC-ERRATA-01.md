## E-01 ／ D-21 更正：`PrimitiveKind.'list'` 与 `FieldKind.'list'` 是两个东西

### 1. 原判断（第 04 批，`BUG-HUNT-CLOSURE-MATRIX.md` §5）

> 「**BH2-004 的三处结论互相冲突**……而**当前 `primitives.ts` 已有 `'list'`**（`:19`、`:129`）」

据此把 BH2-004 定为"待核实 + 文档矛盾"。

### 2. 更正依据（第 05 批实读，本文复核）

| 证据 | 位置 | 内容 |
|---|---|---|
| `FieldKind` 定义 | `src/shared/types.ts:12-25` | 成员 **12 个**：`item/fluid/tag/registry/number/boolean/choice/text/struct/nbt/blockstate/unknown` —— **无 `'list'`** |
| `PrimitiveKind` 定义 | `src/main/schema/primitives.ts:14-25` | 成员含 **`'list'`**（与 `FieldKind` 是**两个不同类型**） |
| `classifyPrimitive` 返回 `'list'` | `primitives.ts:128-129` | `if (field.isArray) return 'list'`（返回类型是 `PrimitiveKind`） |
| `kindForField` 的返回类型 | `src/main/schema/infer.ts:117` | `function kindForField(f: InducedField): FieldKind` |
| `kindForField` 无 `'list'` 分支 | `infer.ts:118-136` | 只映射 `nested/blockstate/nbt/reference/reference_amount/struct`；纯数组 → 落到 `return c.object > 0 ? 'struct' : 'unknown'` → **`'unknown'`** |
| 数组性另由 `multiple` 承载 | `infer.ts:148` | `multiple: f.isArray` |

### 3. 更正结论

| 项 | 原判断 | **更正后** |
|---|---|---|
| `primitives.ts` 的 `'list'` | 被当作 `FieldKind` 有 `'list'` | **属 `PrimitiveKind`**，与 `FieldKind` 无关 |
| 三份报告关系 | "互相冲突" | **实质一致**：都认为不该按缺陷修、都指向"需 UI/产品先支持"；差别仅在措辞（"不构成缺陷"/"已知限制"/"需 UI 支持"） |
| BH2-004 定性 | 待核实 + 文档矛盾 | **描述成立**（数组字段拿不到 `list` 类控件，走 `unknown`）；属**已知限制**，非缺陷 |
| D-21 | 已登记为"文档矛盾" | **建议降级为"误读，非矛盾"** |

### 4. 为什么保留原判断

- `BUG-HUNT-CLOSURE-MATRIX.md` §8 明文规定："若后续 T-10/T-13 推翻了本矩阵的任一判定，**不修改本文件**，另立勘误"。本文件即为该机制的执行。

- R-1 的修改是"**允许 2 条**"，理由是 FIX-01 后 `provider` 内的 `syncPluginLayer()` 与 `ensureSchemas` 各合并一次，**2 条属正常**。

- 二者**共享同一机制**（同一次重建可能产生 2 条日志），但**判定方向不同** → 属**独立问题**。

### 3. 处置

| 项 | 决定 |

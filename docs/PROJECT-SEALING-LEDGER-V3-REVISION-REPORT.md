## 3. `P2-POSIXPATH` 为何独立登记（原验收范围比对）

| 现成条件 | 原验收范围（台账原文） | 是否覆盖 G-3 |
| --- | --- | --- |
| `C7-F2a` | "提交/备份链路：Linux/macOS 下 **rename、权限、行分隔**；覆盖提交、备份、回滚、只读失败" | **否**——文件写入语义，与路径字符串比较无关 |
| `C7-F2b` | "listAndRead/ZIP 链路：POSIX 下**句柄释放、并发行为、内容一致性**" | **否**——ZIP 句柄与内容一致性 |
| `C7-F2`（父） | 源自 `P-C7` §9 F2："跨平台文件系统验证（Linux/macOS：rename、权限、行分隔）" | **否**——父条件原文比 `F2a` 更窄，从未包含导航路径 |
| `P2-SYMLINK` | "词法判定不覆盖软链" | **否**——同子系统但不同缺陷 |

**结论**：导航路径判定（`isPathInsideDir`，基于 `path.relative`）不在上述任一条件的验收范围内。

**本次处置**：
- **未**扩展 `C7-F2a` / `C7-F2b` 的文字；
- **未**新增 `F2c` 子项；
- **未**把 `C7-F2` 的父条件范围改写为"全部跨平台语义"；
- 而是按"不得为维持某数字而改变原验收范围"的约束，**独立登记**为 `P2-POSIXPATH`。

> 说明：另一种做法是经负责人批准扩展 `C7-F2` 并新增 `F2c`，可使总数维持 37。**本次不采用该方案**，因为那会构成范围变更，且需要用"归并"掩盖"父条件定义不完整"这一真问题。

## 4. 共同根因（系统性问题的两个家族）

| 根因 | 涉及发现 | 说明 |
| --- | --- | --- |
| **R-A：插件层与 schema 注册表之间没有同步机制** | BH-004、BH-005 | 注册表有 `upsert` 但**没有按层撤销的能力**，`clearSchemas` 会整体清空，`ensureSchemas` 又只重装 builtin+pinned；`setEnabled` 完全不通知注册表。修一处必须两处一起修 |
| **R-B：`augment()` 的"两遍 `keep` + 共享 `demoted` 数组"设计** | BH-006、BH-007 | 两遍过滤 + 外部可变数组 + 兜底回填，三者叠加产生"降级了又放回去"和"同一字段推两次" |
| **R-C：`call()` 的 `null` 语义被三处消费方各自解释** | BH-009（直接）、BH-010（相关） | `api.ts` 用 `null` 表示失败，但 `null` 同时也是"未知类型"的合法返回值，消费方无法区分。`api.ts` 已提供 `callOrThrow` 却未被这两处使用 |

> **优先修根因而不是逐个打补丁**：R-A 修好可同时消掉 BH-004/BH-005；R-C 修好可同时消掉 BH-009/BH-010。

  4. `setEnabled()` 末尾调用 `syncPluginLayer()`

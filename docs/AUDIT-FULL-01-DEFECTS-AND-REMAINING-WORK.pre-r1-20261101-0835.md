### 1.1 N-01 / N-02 的工程意义（本轮核心发现）

工程内部**存在两套写盘标准**：

| 保护 | `recipes:commit`（提交配方） | `codegen:write`（写脚本/数据包） |
| --- | --- | --- |
| 写盘根校验 | `inside()` 强制在整合包内 | **无** |
| 写前备份 | ✅ `backupOriginalFile`（`wx`，永不覆盖） | ✅ `backupExisting`（但用 `rename` **移动**） |
| 原子写 | ✅ tmp + `fsync` + rename | ❌ `mkdir` + `writeFile` |
| 写后回读校验 | ✅ `canonicalStringify` 比对 | ❌ 无 |
| 失败回滚 | ✅ `failAfterVerify` | ❌ 无 |
| 冲突检测 | ✅ 基线哈希 + 写前守卫 | 仅「文件已存在则要求确认」 |

台账 §3.4 把 `codegen` 的处理记为「**§9-4 已由 `P0-R1` 端到端覆盖**」，但 `P0-R1` 覆盖的是 **handler 级 E2E**，**不含**原子性与根目录校验。因此 N-01/N-02 **确实属于未登记缺口**，不是重复项。

> **说明（不擅自定级）**：N-02 的后果是「原位置缺文件、备份在同目录 `.backup/` 且日志有记录」，属**可恢复**，故按定义判 **P2** 而非 P0（P0 要求「不可恢复丢失」）。若负责人认为「整合包被留在缺文件状态」本身即为不可接受结果，可上调为 P1——**该定级属人工决策，见 §5 D-1。**

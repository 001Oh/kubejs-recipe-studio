## 一、阶段 A：只读检查结论（先检查，后修改）

### C2 单实例锁

- **根因**：`src/main/index.ts` 全仓无 `requestSingleInstanceLock` / `second-instance`（`grep` 为空）。
- **影响**：双开时两个进程共享同一 `userData`（`studio-cache`、`icon-cache`、`uiState.json`、`logs`、备份目录）与同一整合包；P-C7 已把「多实例并发提交」列为未验证风险，本项即其根因。
- **方案**：取锁逻辑抽成可测模块 `singleInstance.ts`；入口在 `whenReady` **之前**取锁，失败即 `app.quit()`；`second-instance` 恢复/聚焦已有窗口，仅在窗口已销毁时重建。
- **预计改动**：`src/main/index.ts`、新增 `src/main/singleInstance.ts`、新增测试。
- **风险**：开发态与打包态共用 userData，可能互相「踢掉」；先如实记录（见 §6 R1）。

### C4 构建图标

- **根因**：`electron-builder.yml` 引用 `buildResources: build` 与 `win.icon: build/icon.ico`，但仓库**不存在 `build/`**；全仓（排除 `node_modules`/`out`/`.cache`）**没有任何 `.ico` / `.icns` / logo 位图**。
- **影响**：`npm run dist:win` 找不到图标 → 回退默认 Electron 图标并告警（部分版本直接失败）；发布门面不合格。
- **方案**：**不生成临时品牌图标**。建立 `build/` 并写明所需资源规格与验证方式，保持 yml 引用不变（保留明确意图）。
- **风险**：在资源到位前，打包仍不可用（这是**已知阻塞**，不是本次修复遗漏）。

### C5 文件白名单

- **根因**：`files` 白名单含 `node_modules/yauzl-promise/**`，但 `package.json` 依赖只有 `acorn`、`yauzl`；`package-lock.json` 无该包；`node_modules` 无该目录；源码 0 处引用。
- **实际依赖链**：`yauzl@3.4.0 → pend@1.2.0`；`fd-slicer@1.1.0 → pend`（`fd-slicer` 仅被 `extract-zip` 内的 `yauzl@2.10.0` 使用，属 dev 链）。
- **方案**：删除无效项 `node_modules/yauzl-promise/**`；不改 ZIP 实现、不动 P-OPT4。

### C9 导航安全

- **根因**：`window.ts` 只有 `setWindowOpenHandler`（新窗口拒绝 / https 交系统浏览器），没有 `will-navigate`；主窗口可被渲染进程导航到任意外部地址。
- **影响**：误点/注入可让主窗口离开应用页面（应用为本地内容，风险有限但不合最佳实践）。
- **方案**：新增 `navigation.ts` 纯策略 + 守卫：开发态只允许与 dev server **同源**的 http(s)，生产态只允许 `file://` 下渲染目录内的页面；其余 `preventDefault` 并记 WARN。**不禁止**同源内部路由/hash，**不放宽** `webSecurity`，**不新增**权限。
- **风险**：若将来新增独立窗口需复用同一守卫（见 §6 R2）。

## 六、未完成事项与新增风险

### 未完成

1. **图标资源缺失（阻塞发布）**：需项目负责人提供 `build/icon.ico`（及可选 png/icns）；在此之前 `dist:win` 不可用于正式发布。
2. **未打包 / 未做安装与卸载测试**：任务明确禁止。
3. **开发态与打包态共用 userData**：单实例锁会让「已安装版」与 `npm run dev` 互相抢占（后启动者退出）。未改路径策略，需产品决策（建议 dev 用独立 `userData`，例如 `--user-data-dir`）。
4. **`fd-slicer` 白名单保留**：运行非必需但无害，未在本次删除。
5. **导航守卫仅覆盖主窗口**：将来若新增 BrowserWindow，需复用 `installNavigationGuards`。

### 风险

| # | 风险 | 等级 | 说明 |
| --- | --- | --- | --- |
| R1 | 开发态/打包态互相踢出 | Medium | 两者 userData 相同；如需并行调试，需显式指定不同 `--user-data-dir` |
| R2 | 新窗口绕过导航守卫 | Low | 目前只有主窗口；新增窗口须显式安装守卫 |
| R3 | `will-navigate` 只拦渲染进程发起 | Low | CDP 的 `Page.navigate`（自动化/调试）不经此事件，属浏览器语义，不是漏洞 |
| R4 | 单实例锁依赖 Electron 默认锁文件 | Low | 同一 userData 才互斥；不同 userData 可并存（符合预期） |
| R5 | 图标缺失导致发布阻塞 | **High** | 明确阻塞项，等资源 |

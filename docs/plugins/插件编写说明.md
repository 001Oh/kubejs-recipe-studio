# 插件编写说明（模组支持插件）

对应需求：`docs/KubeJS配方工坊-需求规格-完整版.md` §3.6.14。可直接照抄的样例：`plugins/examples/occultism-ritual.json`。

## 0. 先记住一句话：插件是加速项，不是必需项

没装插件时，该模组的配方**照样能编辑**——程序会用 L1 反推（从本包真实配方 JSON 里归纳字段）自动生成表单。
装了插件只是多了三件事：字段中文名、前置条件提示、精确的约束（必填 / 数量范围 / 枚举取值）。

所以：**两者是叠加关系，不是替代关系**。插件没写到的字段，仍然由 L1 补全，绝不会因为装了插件就丢掉实测字段。

最有价值的用法：整合包作者为自己包里的魔改打包插件，玩家导入整合包即自动获得精确支持，不需要额外装任何东西。

## 1. 放哪里

两个来源，**前者优先**：

| 位置 | 用途 |
| --- | --- |
| `<整合包>/.recipe-studio/plugins/` | 跟随整合包分发（作者打包魔改支持） |
| `userData/plugins/` | 用户级，跨整合包复用 |

两种落法都可以：

- 单文件：`plugins/occultism-ritual.json`
- 目录（JS 钩子为**预留能力**，当前版本未接入执行流程，见 §8）：`plugins/occultism-ritual/manifest.json` + 同目录的 `ritual.js`

同目录内按文件名排序，因此**整合包内第一个生效**；用户目录里的同名类型声明会被压掉，并在插件管理页标出冲突（不会静默消失）。
插件 id 相同的两份插件，低优先级那份显示为「已禁用：插件 id 与更高优先级来源重复」。

> 注意：真实整合包在本程序里是只读的。给自己包写插件时请由包作者随包发布，或放到 `userData/plugins/`。

## 2. manifest 全字段

除 `id` / `name` / `version` 外**全部可选**，缺了不报错——这就是「部分覆盖」的门槛。

| 字段 | 类型 | 作用 |
| --- | --- | --- |
| `id` | string | 插件唯一标识（必填） |
| `name` | string | 显示名（必填） |
| `version` | string | 插件自身版本（必填，写 `1.0.0` 这种） |
| `author` | string | 作者，管理页展示 |
| `appVersion` | string | 兼容的程序版本范围，见 §6 |
| `mods` | string[] | 依赖的模组 modId。**其中有未安装的模组 → 整包禁用**并写明缺哪个 |
| `kubejsAddon` | string \| null | 依赖的 KubeJS 附属 modId（如 `kubejs_create`），见 §5 |
| `recipeTypes` | object[] | 接管哪些配方类型及其参数结构，见 §3 |
| `fieldNames` | {键: 中文名} | 全局字段词典；键就是配方 JSON 里的字段名 |
| `valueNames` | {值ID: 中文名} | 全局枚举值词典；键是 `modid:value` 形式 |
| `virtualItemPatterns` | string[] | 虚拟物品过滤规则，见 §7 |
| `hooks` | {类型ID: 文件名.js} | 可选 JS 钩子，见 §8 |

写错字段名不会崩：程序会在日志里点名 `manifest.apppVersion：未知字段，已忽略`，帮你抓到拼写错误。

最小可用的「只改中文名」插件（参数结构仍由 L1 反推填充）：

```json
{
  "id": "my-pack-field-names",
  "name": "本包字段中文名",
  "version": "1.0.0",
  "fieldNames": { "pentacle_id": "法阵等级", "max_times": "可重复次数" },
  "valueNames": { "occultism:craft_djinni": "巨灵加工法阵（Tier 2）" }
}
```

## 3. 配方类型声明（recipeTypes 的每一项）

字段名与程序内部 schema 一致，可以直接照抄配方 JSON 的键。

| 字段 | 说明 |
| --- | --- |
| `id` | 配方类型 ID，必须写全 `命名空间:名称`，如 `occultism:ritual` |
| `displayName` | 类型显示名，如「神秘学 · 仪式」 |
| `modId` / `modDisplayName` | 可省略，缺省从 `id` 的命名空间推 |
| `layoutKind` | **只能**是内置六值：`shaped` / `shapeless` / `single_io` / `multi_io` / `sequence` / `custom` |
| `emitTarget` | 语法糖目标，如 `event.recipes.create.mixing`；写 `null` 表示走 `event.custom` / 数据包 |
| `customTemplate` | 生成时垫底的 JSON 模板，如 `{ "type": "occultism:ritual" }` |
| `slots` / `outputs` / `extraFields` | 参数槽位数组，见 §4 |
| `modifiers` | 链式修饰符（`heated` / `processingTime` 之类）：`{ key, displayName, kind: "boolean"\|"number", chain?, min?, max? }` |
| `requirements` | 前置条件文案：`["需要搭建仪式祭坛", { "kind": "structure", "text": "…" }]`，`kind` ∈ `structure/time/dimension/research/other` |
| `notes` | 类型级提示（如「AE2 压印器模板不消耗」） |
| `grid` / `cells` | `custom` / 有序网格布局用：`{ "rows": 3, "cols": 3, "maxRows": 9 }`、`[{ "key": "input", "row": 0, "col": 0 }]` |
| `supportsChance` | 该类型是否支持产出概率 |
| `docUrl` | 文档链接 |

**插件不得自定义 UI 组件。** 写了别的 `layoutKind`（比如 `my_fancy_grid`）会被拒绝：日志给出六个允许值并丢弃那一条声明，插件其余部分照常工作。

## 4. 槽位（slots / outputs / extraFields 的每一项）

| 字段 | 说明 |
| --- | --- |
| `key` | 配方 JSON 里的真实字段名（必填，缺 key 的槽位被丢弃） |
| `displayName` | 中文名；省略时自动套 `fieldNames` 词典 |
| `kind` | `item` / `fluid` / `tag` / `registry` / `number` / `boolean` / `choice` / `text` / `struct` / `nbt` / `blockstate`；认不出的值一律按 `unknown` 进「高级参数」区 |
| `multiple` | 是否可放多个 |
| `required` / `min` / `max` | 约束 |
| `registry` | `kind: "registry"` 时写注册表 ID，如 `mekanism:infuse_type` |
| `emitShape` | 生成形态：`scalar` / `object` / `positional` |
| `role` | **`requirement` 的字段会汇总进前置条件摘要条**；另有 `input` / `output` / `extra` |
| `zone` | 视觉分区：左材料 / 右产物 / 下附加 |
| `choices` | 枚举项：`["a", "b"]` 或 `[{ "value": "a", "label": "甲" }]`，label 缺省自动查 `valueNames` |
| `choicesSource` | 写 `"values:<任意名>"` 时，枚举项直接取本插件 `valueNames` 词典的全部条目 |
| `defaultValue` | 默认值 |
| `compound` | 合并进本控件的原始键名（生成 JSON 时还原） |
| `sugarSupported` | 写 `false` 表示语法糖表达不了该字段，用户填了会触发降级 |
| `orientation` / `firstItemMust` | 竖排（AE2 压印器 top/middle/bottom）、首项固定约束 |
| `fields` | `kind: "struct"` 的子字段（子字段请用内联 `choices`） |

## 5. 与 KubeJS 附属检测联动

`kubejsAddon: "kubejs_create"` 时程序按 §3.6.1 的扫描结果自动决定通道，**不需要用户手动判断**：

- 附属已装 → `emitTarget` 生效，生成 `event.recipes.create.mixing(...)` 语法糖，徽章 `✓ 语法糖`
- 附属未装 → **自动降级为数据包 JSON**，徽章 `✓ 兼容`，并在插件列表写明「因未安装 KubeJS Create，已切换为数据包模式」

`mods` 里写了未安装的模组则整包禁用（连词典一起撤出），原因同样显示在列表里。
判定依据只有扫描出的 `installedModIds` / `kubejsAddons`；两者都查不到（例如还没扫描）时**不做降级**，宁可用语法糖也不误杀插件。

## 6. appVersion 兼容判定

支持的写法（程序内置最小 semver，不引第三方库）：

```
>=1.0.0     ^1.2.0     ~1.2.3     1.2.0     1.2     *
>=1.0.0 <2.0.0          （空格 = 并且）
1.0.0 || >=3.0.0         （|| = 或者）
```

不匹配（或范围写错，例如误写成 `=>1.0.0`）时插件状态为 `✗ 不兼容`，列表里写明「需要 app …，当前 …」，**不会静默消失**，也不会进 schema 注册表。

> 当前程序版本还处在 0.x：样例里写 `">=0.1.0"`。规格示例中的 `">=1.0.0"` 是示意写法，在 0.x 版本下会被标为不兼容。

## 7. 虚拟物品过滤规则

`virtualItemPatterns` 用通配：`*` 匹配同一路径段内的任意串（不跨 `/`），`?` 匹配单字符，整体不区分大小写。

```json
"virtualItemPatterns": ["occultism:ritual_dummy/*"]
```

命中 `occultism:ritual_dummy/greater_ritual`，不命中 `occultism:ritual_dummy`、`occultism:ritual`、`create:ritual_dummy/x`。
这些物品在侧边栏默认隐藏（可用「显示虚拟物品」开关放行），因为它们只是配方的「密钥」，不会进玩家背包。

## 8. JS 钩子（预留能力，当前版本未接入）

> **状态（B121/D-49.1，2026-11-06）**：本节描述的沙箱已实现并有完整测试（`src/main/plugins/hookSandbox.ts`），
> 但当前版本**尚未接入生产插件执行流程**——manifest 里写 `hooks` 不会被执行，日志也不会出现钩子相关记录。
> 接入前本节仅作设计文档阅读；「JSON 插件路径严禁任何代码执行」的约束不受影响。

只有 manifest 里写了 `hooks` 才会走沙箱；**JSON 插件路径严禁任何代码执行**。

```json
"hooks": { "occultism:ritual": "ritual.js" }
```

```js
// ritual.js —— 返回一段 KubeJS 代码文本
module.exports = function (recipe) {
  var id = recipe.values.activation_item.id
  return 'event.custom({ type: "occultism:ritual", activation_item: ' + quote(id) + ' })'
}
// 也支持 exports.emit = function (recipe) { … }
```

沙箱能用的东西（`src/main/plugins/hookSandbox.ts`）：

- 数据：`recipe.typeId` / `recipe.values` / `recipe.modifiers` / `recipe.pluginId`（由 JSON 往返生成在沙箱内，拿不到任何宿主对象）
- 内置：`JSON` / `Math` / `Object` / `Array` / `String` / `Number` / `Boolean` / `Date` / `RegExp` / `Map` / `Set`
- 助手：`item(id, count)` / `tag(id, count)` / `fluid(id, amount)` / `fieldName(key)` / `valueName(id)` / `quote(text)` / `list(parts, sep)`

明确禁止（静态扫描 + `vm` 关掉字符串代码生成，双层）：`require` / `import` / `process` / `globalThis` / `fs` / `net` / `http(s)` / `dns` / `tls` / `child_process` / `fetch` / `XMLHttpRequest` / `WebSocket` / `Buffer` / `WebAssembly` / `Atomics` / `SharedArrayBuffer` / `Symbol` / `constructor` / `prototype` / `__proto__` / `eval` / `Function` / 定时器。
钩子必须**同步返回字符串**，执行超过 **1000ms 强杀**；插件文件上限 64KB；钩子路径不许逃出插件目录，只收 `.js` / `.cjs`。

被拒时插件不会连累程序启动：日志记 WARN，该次生成退回 JSON 通道。

## 9. 写完之后怎么自查

1. 启动程序，打开「设置 → 插件」。这一页会列出：状态、版本、覆盖类型数、来源、降级原因。
   （冲突明细与「未覆盖类型 N 个」统计已在 plugins/report.ts 实现，
    但当前版本尚未接入管理页，为预留能力。）
2. 插件没出现在列表里 = 目录或文件名不对（检查是否落在 §1 的两种位置、后缀是否 `.json` / `manifest.json`）。
3. 状态 `✗ 解析失败` 后面直接跟着字段名，例如 `name：缺少非空字符串 name`、`recipeTypes[0].layoutKind：只允许内置布局 …`。
4. 想看细节去日志抽屉，来源筛 `PLUGIN`：单条声明被忽略、词典冲突、钩子被拒都只记 WARN，不影响其余插件。
5. 关掉某个插件用列表里的开关（状态变「已禁用：已在插件管理页关闭」），它的类型覆盖与词典会一起撤出，重新打开即恢复。

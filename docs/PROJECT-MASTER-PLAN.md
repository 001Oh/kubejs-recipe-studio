## 1. 治理规则（先定规则，再排任务）

### 1.1 任务状态机（八态，互斥）

| 状态 | 含义 | 允许的下一步 |
|---|---|---|
| 未开始 | 尚未动工 | 进行中 / 待决策 / 受阻 |
| 进行中 | 正在执行 | 待验收 / 受阻 / 未通过 |
| 受阻 | 缺前置、缺授权或环境不可用 | 进行中（解除后） |
| 待决策 | 需负责人裁定 | 进行中（有决定后）/ 已接受为已知限制 |
| 待验收 | 执行完成但证据未核 | 已通过 / 未通过 |
| 已通过 | **证据充分且已独立核对** | — |
| 未通过 | 验收不达标 | 进行中（返工）/ 待决策 |
| 已接受为已知限制 | 经决定不再修 | — |

> **铁律**：报告写"已完成"但无对应证据 → **只能记 `待验收`**（V9 §3.8 与 BUG-HUNT-04 §9.1 同口径）。

### 1.2 三层证据口径（不得混用）

| 层 | 判定条件 | 可否用于"关闭" |
|---|---|---|
| ① 代码已改 | 源码哈希 + diff | 否 |
| ② 测试通过 | 指定用例在 `node` 环境通过 | 否（除非条件本身就是测试类） |
| ③ 真实环境已验证 | 启动应用 + 真实整合包 + 可复核证据 | **只有 ③ 才能关闭"发布/真实行为"类条件** |

### 1.3 授权等级（每个任务必须标注）

| 级别 | 允许动作 | 本批（第 01 批）授权 |
|---|---|---|
| A0 | 只读核查 | ✅ |
| A1 | 写 `docs/` 计划与报告 | ✅ |
| A2 | 改源码 + 测试 | ❌ 需按批次单独授权 |
| A3 | 运行测试/typecheck/lint | ✅（本轮已用，仅只读校验） |
| A4 | 启动应用 / 真实整合包 | ❌ 需单独授权 |
| A5 | 构建 / 打包 / 安装 / 发布 | ❌ 需单独授权 |

### 1.4 每批执行门禁（全部满足才算通过）

1. 保护边界核对（V9 MD5 不变、未碰生产 userData、`dist*`/cache 未动）。
2. 改动文件清单 + 每个文件修改前后 SHA-256。
3. 目标任务的验收证据（按 §1.2 分层标注）。
4. 回归：相关用例 + 完整套件 + typecheck + lint 实际结果。
5. 既有测试未被删除/跳过/放宽（对比用例数与 skip/todo 清单）。
6. 回滚命令可执行且经哈希验证。
7. 本计划与 CHANGELOG 已同步（新增/变更任务必须先改计划）。

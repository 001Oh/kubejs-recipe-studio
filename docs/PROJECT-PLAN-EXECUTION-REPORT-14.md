## 2. 方案重审：修正第 13 批的两处缺陷

### 2.1 缺陷一（严重）：第 13 批声称"消除混合世代"，只对**单目录**成立

第 13 批 §6.1 写"把混合世代内容这一最难判定的状态彻底消除了"。**这句话在 C-7 上不成立**：
C-7 要动 `src` **和** `tests` 两个目录，两个目录各自 2 次 `rename`，共 4 次。若在"`src` 已换、`tests` 未换"处中断，得到的是
**`src` = 旧世代 + `tests` = 新世代** —— 这是**跨目录的混合世代**，而且它**不可编译**（旧 `loader` 没有 `getPluginLoadStatus`，
而新 `tests` 里的两个测试文件引用它）。

**修正**：给切换定**固定顺序**，并证明"任何中间态都可编译"。

### 2.2 修正：切换顺序 `tests → src`，还原顺序 `src → tests`（镜像）

| 中间态 | 是否可编译 | 实测 |
|---|---|---|
| `src` 新 + `tests` 旧（**先切 tests** 后的中间态） | ✅ | **本批 `tsc` = 0 错误**（`.cache/fix14/mid`，见 §4.1） |
| `src` 旧 + `tests` 新（**先切 src** 后的中间态） | ❌ | 第 13 批 V4 已测：17 处 `TS2339` |
| `src` 旧 + `tests` 旧（目标世代） | ✅ | 第 13 批 V5 = 0 错误 |
| `src` 新 + `tests` 新（演练前后） | ✅ | 第 13 批 ctl = 0 错误 |

**为什么 `tests` 旧 + `src` 新反而可编译**：C-7 的旧测试文件（`schemaMerge.test.ts`、`hookBlacklist.test.ts`）**不引用**新 API，
它们对新 `src` 完全兼容；真正冲突的是**两个后于备份新增的测试文件**，而它们已在世代构造时被排除（D-26）。
于是整个演练过程里，**任何时刻的树都能通过 `tsc`** —— 这让"中断后继续排查"成为可能，而不是面对一棵编译不过的树。

**代价（诚实说明）**：这条顺序只对"C-7 这一类**新增测试晚于备份**"的场景有效。
若未来备份晚于全部测试，则顺序对可编译性无影响；若备份早于**源码 API 新增**且调用方也在清单外，则任何顺序都救不了（C-6 即此类，见 §6）。

### 2.3 缺陷二（中等）：第 13 批的"临时移出"落点选错

第 13 批 §5.1/§5.2 把"移出 2 个测试文件"设计为在 `gen/parked/` 里**物理移动**，并且 `prev/` 与 `parked/` 是两套目录。
这带来两个多余的中断点（移出、移回各一次）与一次"文件级操作"混进"目录级切换"。

**修正（D-26 的等效但更安全的实现）**：
**世代副本在构造时就不复制这 2 个文件**；冷备里**完整保留**它们。
于是"演练期间这 2 个文件不在有效树中"由**目录 rename 的原子性**保证（整目录一次换掉），
"逐字节恢复"由**还原时把冷备整目录 rename 回来**保证 —— 全程**没有任何文件级的删/移/写**。

| D-26 要求 | 本实现如何满足 |
|---|---|
| 必须先保存并核对文件内容和哈希 | 冷备 `cold/tests/` 含这两个文件；`manifest-cold.json` 含其 SHA-256；冷备建立时**回读校验**（§3.2 C-4） |
| 演练期临时移出 | 世代副本中**不存在**（构造时排除，`excluded=2`，已实测） |
| 结束后逐字节恢复 | 还原 = `rename(cold整目录 → live)`，两个文件随之回归；终态全量哈希 == 冷备 |
| 不得删除/弱化/永久移除测试 | 真实 `tests/` **从未被删过任何文件**；冷备原样保留；还原后 94 文件 |
| 最终工作区与演练前一致 | §3.5 终态校验 T-1～T-5 |

> **保留备选**：若负责人坚持"必须看到物理移出动作"，可在 `gen/` 之外另设 `parked/` 做真实 `rename` 移动。
> 但那会**多两个中断点**、且把文件级操作混入目录级切换，本报告不推荐。

### 3.3 恢复命令（**人工可复制的逐条命令**，不依赖脚本）

> 前提：`cd "E:/mc kjs"`，并设 `R=.cache/fix14/<run-ts>`。
> 判定依据**只有三件事**：`<目录>` 是否存在、其全量哈希等于哪一代、`prev/` 是否存在。
> **不需要读 journal**（journal 可能因崩溃丢最后一行，哈希不会说谎）。

```bash
# ① 先看状态（不改任何东西）
ls -d src tests "$R"/prev/src "$R"/prev/tests "$R"/gen/src "$R"/gen/tests 2>/dev/null
sha256sum src/main/plugins/loader.ts tests/main/schemaMerge.test.ts   # 与 manifest 对照

# ② 若 src 缺失（缺口窗口 / 还原第一段之后）
mv "$R"/prev/src src

# ③ 若 tests 缺失
mv "$R"/prev/tests tests

# ④ 若某目录仍是"旧世代"（哈希 == manifest-gen.json）→ 回滚该目录
mv src "$R"/retired/src && mv "$R"/prev/src src          # 以 src 为例
mv tests "$R"/retired/tests && mv "$R"/prev/tests tests  # tests 同理

# ⑤ 终态核对（必须 278 条全等）
node .cache/fix14/drill.mjs --root . --stage verify --expect cold
```

> `mv` 在此处等价于 `rename`（同卷），**不要**用 `cp -r` 覆盖（会改变 inode 且可能被句柄阻塞）。
> 若 `mv` 报 `Permission denied`：说明目录内有打开的句柄，关掉编辑器/终端里 `cd` 进去的会话后重试。

## 5. 非原子性声明与残余风险

### 5.1 明确声明（按指令要求）

> **本方案不具备真正的原子性。**
> Windows 上 `rename` 无法覆盖已存在的目录（第 13 批 P-1/P-1b：连空目录也 `EPERM`），
> 也无法原子替换 junction（P-3），因此目录级切换**必然是两段 rename**，
> 中间存在 **`live` 目录完全不存在的窗口**，实测 **中位 1.015 ms / 最大 1.204 ms**。
> **不得在任何文档或对外表述中声称本方案"原子"、"事务性"或"可自动回滚"。**
> 准确表述是：**"中断后可检测、可确定性恢复，但需要再跑一次恢复命令。"**

### 5.2 ③（沙盒）到 ④（真实）之间的差异项

| # | 差异 | 影响 | 是否已缓解 |
|---|---|---|---|
| R-1 | 沙盒**没有跑 `vitest`**，只跑 `tsc` | 真实换入后 vitest 的具体失败**形态与条数**未知 | 只能由 ④ 回答；不影响数据安全 |
| R-2 | 真实工作区有 `.cache/pc*-pack-1112`（`nlink=4` 硬链接）等邻居 | 若误用通配符清理会误伤 | 演练只做 `rename`，**不做任何删除**；`.cache/fix14` 为新建独立目录 |
| R-3 | 真实工作区有 `out/`、`node_modules/.vite` 缓存 | 换入后 vite 可能命中旧转换缓存，导致 O-1 结果失真 | 换入前不构建；如结果异常，先按"缓存污染"排查再下结论 |

## 1. 统一后的候选集口径

"原始条目总数"不是报告里现成的数字，它由候选集规则决定。v1 声明了 R1–R4 却在计算时违反 R1，v2 固定为五条规则，并在后续每一层标注引用。

| 规则 | 内容 | v2 的执行方式 |
| --- | --- | --- |
| **R1 条目化** | 只取报告中**以条目形式编号/列表**的"遗留 / 风险 / 未完成 / 尚未验证"项 | 结论段落里的约束句（如 `P-OPT4` §5 "封板后不再改动 P-OPT 路径"）**一律不入池** |
| **R2 同报告内去重** | 同一报告中"风险表"与"未完成表"陈述同一批事项时，只计一次 | 以"未完成 / 已确认问题"表为准，风险表作复述处理 |
| **R3 跨表覆盖** | 已被另一条目在语义上完整覆盖者，不单独计，但**必须在台账写明覆盖关系** | 仅 `P0` §9-4 → `P0-R1` 一处 |
| **R4 缓解项不计** | 自评 Low、已有测试覆盖、无待办动作的风险不登记为条件 | 仅 `P0` §10-R4 一处 |
| **R5 不并比不列更差** | 若某项的归并需要**扩大既有条件的验收范围**，则不得归并，只能登记为独立条件 | 用于裁定 G-3（见 §5） |

> R5 是 v2 新增。它的作用是防止"为了凑数而归并"——归并只能在**原验收范围已经覆盖**的前提下成立。

## 2. 修正 1：C1 移出候选池，重新计算

### 2.1 C1 的性质（事实认定）

`P-OPT4-最终验收与封板.md` 的结构是：`§4 已知风险`（编号 1–8，共 8 条）+ `§5 验收结论`（纯段落，**无任何编号条目**）。

台账的 `OPT4-C1` 取自 §5 结论第二句："封板后除缺陷修复外，不再改动 P-OPT 涉及的扫描/写入/zip 路径"。

- 它是**约束**（对后续开发的限制），不是**待办**（需要完成才有意义的动作）；
- 它没有验收标准、没有关闭条件、没有责任动作；
- 按 R1，它**不具备条目资格**。

**因此：OPT4 的候选数 = 8（不是 9），C1 不入池、不参与任何加减。**

### 2.2 v1 的算式为什么错

v1 写 `① 42（含 C1）→ ④ −1（C1 移出）`。这在算术上是空转（先加后减），但会造成两个实际危害：

1. 让读者以为 OPT4 有 9 个遗留条目（实际 8 个）；
2. 掩盖了 v1 真正的漏项——打包簇少算了一个来源（见 §2.3）。

### 2.3 v1 真正的算术错误：打包簇是 4 个来源，不是 3 个

v1 把打包簇写成 3 个来源（`P2`§11-1、`UI`U6、`P1`§六-2），漏掉了 `P0` §9-5「**未做打包后验证**（任务禁止打包）」。这四个来源陈述的是同一件事：

| 来源 | 原文 |
| --- | --- |
| `P2` §11-1 | "正式安装版未实测……未在 `.exe` 上验证" |
| `UI` §10 U6 | "打包产物（`dist:win`）未验" |
| `P1` §六-2 | "未打包 / 未做安装与卸载测试" |
| `P0` §9-5 | "未做打包后验证（任务禁止打包）" |

四者合并为 `REL-PKG`（并新增审计 C3 的 asar worker 冒烟要求）。**簇规模从 3 改 4，归并扣减从 −3 改 −4。** v1 因漏算这 1 条，被迫在别处多补 1 条（把 C1 塞进池），于是总数看起来仍然对——这正是"42 在两种构成下都成立"的原因。

### 2.4 重新计算（C1 不入池 + 打包簇 4 源）

| 步骤 | 动作 | 数量 | 动作类型 |
| --- | --- | --- | --- |
| ① | 已归属来源合计（见 §2.5） | **42** | — |
| ② | `OPT4-R1` → `C7-F2` | −1 → 41 | 并入既有 ID |
| ③ | `OPT4-R5` → `C7-F3` | −1 → 40 | 并入既有 ID |
| ④ | `UI-U6` → `REL-PKG` 簇 | −1 → 39 | 并入合成项 |
| ⑤ | `P1`§六-2 → `REL-PKG` 簇 | −1 → 38 | 并入合成项 |
| ⑥ | `P2`§11-1 → `REL-PKG` 簇 | −1 → 37 | 并入合成项 |
| ⑦ | `P0`§9-5 → `REL-PKG` 簇 | −1 → 36 | 并入合成项 |
| ⑧ | 新增合成条件 `REL-PKG`（4 源 + 审计 C3） | +1 → **37** | 新增 |

**②–⑦ 六步全部是同一动作类型（并入另一条已有 ID），无一步是"移出"或"排除"。** 这是 v2 相对 v1 的最大改进：算式里不再混用两种语义，任何一步都可以单独复核。

### 2.5 42 的构成（v2 版，注意与 v1 不同）

| 组 | v1 的构成 | **v2 的构成** | 差异 |
| --- | --- | --- | --- |
| P-C7 | 7 | 7 | — |
| P-OPT4 | 8 + **C1 1** = 9 | **8**（C1 出池） | **−1** |
| UI | 6 | 6 | — |
| P0 | 6 | **7**（补入 §9-5；剔除 §10-R5 未登记） | **+1** |
| P1 | 5 | 5 | — |
| P2 | 9 | 9 | — |
| **合计** | **42** | **42** | 净 0（−1 与 +1 抵消） |

> **必须写明的事实**：v1 与 v2 都得 42，但**成员不同**。v1 的 42 含 C1、不含 §9-5；v2 的 42 不含 C1、含 §9-5。这是两次错误相互抵消留下的"巧合数字"，也是前几轮一直没发现问题的原因。**今后引用 42 时必须同时引用构成，不能只引数字。**

## 3. 修正 2：P2 §11-4 的单一口径

| 项 | v1 的写法 | v2 的写法 |
| --- | --- | --- |
| P2 §11-4（`--user-data-dir` 显式传入时不追加 `-dev`，开发者手动指向 prod 目录仍会共享数据） | 同时出现在 X-7（"被排除项"）与 G-1（"真遗漏"），且 X-7 的理由栏自己写着"**无理由**——既非重复也非缓解项" | **只作为 G-1 存在**：它是合格候选（入池），只是台账没给它 ID（未登记） |

**因此**：X 列表删除该项；`P2` 入池数从 9 升为 11（含 §11-4 与 §13-4）；已归属数仍为 9（这两项没有 ID）。

## 5. 修正 4：G-3 不能并入 C7-F2（依原验收范围判定）

### 5.1 候选对象

`P2` §13-4：「非 Windows 平台（`path.relative` 大小写处理按平台分支，POSIX 未实测）」。

### 5.2 依原验收范围逐项比对

| 现成条件 | 原验收范围（台账原文） | 是否覆盖 G-3 |
| --- | --- | --- |
| `C7-F2a` | "提交/备份链路：Linux/macOS 下 **rename、权限、行分隔**；覆盖提交、备份、回滚、只读失败" | **否**。范围是文件写入语义（rename 覆盖、EPERM、行分隔符），与路径字符串比较无关 |
| `C7-F2b` | "listAndRead/ZIP 链路：POSIX 下**句柄释放、并发行为、内容一致性**" | **否**。范围是 ZIP 句柄与内容一致性 |
| `C7-F2`（父） | 来自 `P-C7` §9 F2：「跨平台文件系统验证（Linux/macOS：rename、权限、行分隔）」 | **否**。父条件原文的范围**比 F2a 更窄**，且出自性能/扫描阶段，从未包含导航路径 |
| `P2-SYMLINK` | "词法判定不覆盖软链" | **否**。同一子系统，但不同缺陷（软链 vs 大小写） |

**判定：G-3 落在 `C7-F2a` 与 `C7-F2b` 之间的空隙里——两个子项的字面范围都够不着它。**

### 5.3 因此不能说"并入 C7-F2 即可"

v1 的建议是"建议增列 F2c，否则该条永远关不掉"。这个理由本身是对的（确实关不掉），但**结论是错的**：把一项并进一个范围不含它的父条件，等于用归并掩盖了"父条件定义不完整"这个真问题。而且 `C7-F2` 是 `P-C7` 阶段的产物，其范围由该阶段报告定义；`P2` 新增的导航守卫是后来才出现的子系统，**跨阶段扩张别人的条件范围，需要原条件负责人的确认，不能由统计口径自行决定**。

**v2 的判定**（适用 R5）：

| 方案 | 内容 | 总数 | 前提 |
| --- | --- | --- | --- |
| **A（默认建议）** | 登记为独立条件 `P2-POSIXPATH`（未解决·低·后续改进；关闭所需：POSIX 实机验证 `isPathInsideDir` 大小写与分隔符行为） | **38** | 无需额外批准，按"有遗留就要有 ID"的规则直接登记 |
| B（备选） | 经批准扩展 `C7-F2` 父条件定义、新增子项 `F2c`，并同步修改 `F2a`/`F2b` 的文字使三者并列 | 37 | **须原条件负责人书面确认范围变更**；不得由本报告自行决定 |

**默认走 A，即总数不是 37 而是 38。** 为维持 37 而选 B，必须留下批准记录；本报告不替负责人做这个决定。

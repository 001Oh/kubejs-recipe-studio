## 1. 治理规则

### 1.1 任务八态（互斥，不得自造）

| 状态 | 进入条件 | 离开条件 |
|---|---|---|
| 未开始 | 尚未动工 | → 进行中 / 待决策 / 受阻 |
| 进行中 | 正在执行 | → 待验收 / 受阻 / 未通过 |
| 受阻 | 缺前置/授权/环境 | → 进行中（解除后） |
| 待决策 | 需负责人裁定 | → 进行中 / 已接受为已知限制 |
| **待验收** | 执行完成但证据未核，或验收条件只达成一部分 | → 已通过 / 未通过 |
| 已通过 | **证据充分且已独立核对** | — |
| 未通过 | 验收不达标 | → 进行中（返工）/ 待决策 |
| 已接受为已知限制 | 经决定不再修 | — |

> **铁律**：报告中写「已完成」但无对应证据 → **只能记 `待验收`**。

### 1.2 三层证据（不得混用）

| 层 | 判定条件 | 能否关闭「发布/真实行为」类条件 |
|---|---|---|
| ① 代码已改 | 源码哈希 + diff | 否 |
| ② 测试通过 | 指定用例在 node 环境通过（**须有本次执行输出**） | 否（除非条件本身即测试类） |
| ③ 真实环境已验证 | 启动应用 + 真实整合包 + 可复核证据 | **仅 ③ 可以** |

### 1.3 决策五态

`已登记` → `待决策` → `已答复` → `已实施` → `已验证`，**五态不得互相替代**。

**本版实际计数（截至第 20 批）**：已登记 **31** ｜ 已答复 **11** ｜ 已实施 **2** ｜ 已验证 **0** ｜ 待决策 **20**。

> 依据：`PROJECT-DECISIONS.md` §9.3。v1.1 §1.3 写「20 项全部停在待决策」已过时，本版据实更新。

### 1.4 统计纪律

| 规则 | 内容 |
|---|---|
| **S-1** | **所有计数必须从逐行表重算**，禁止沿用任何汇总数字 |
| **S-2** | 每个数字必须注明**来源文件 + 章节 + 统计规则** |

### 3.1 为什么新增 P0.5（本版核心设计）

v1.1 存在 **C-1 规则死锁**：

```
① T-02 通过 ← 需要「恢复演练通过」
② 演练      ← 需要回滚工具
③ 工具      ← 存在 5 项阻断缺陷（R-01/02/03/04/07）
④ 修工具    ← 若属「代码批次」，被硬约束①禁止
⑤ 硬约束①解除 ← 条件正是 T-02 通过
```

**根因不在规则太严，而在计划结构缺一类任务**：回滚工具维护既不是产品代码批次，也没有独立归属，只能靠「负责人临时解释例外」，导致审计链无根（风险记录 P-1/P-2）。

**P0.5 的解法**：把「回滚工具维护」提升为**计划层的一等任务（T-23）**，置于 T-02 之前、P2 之外。它**不修改任何验收标准**，只修正任务归属与执行顺序。

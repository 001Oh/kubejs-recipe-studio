## 1. 治理规则

### 1.1 任务八态（互斥，不得自造）

| 状态 | 进入条件 | 离开条件 |
|---|---|---|
| 未开始 | 尚未动工 | → 进行中 / 待决策 / 受阻 |
| 进行中 | 正在执行 | → 待验收 / 受阻 / 未通过 |
| 受阻 | 缺前置/授权/环境 | → 进行中（解除后） |
| 待决策 | 需负责人裁定 | → 进行中 / 已接受为已知限制 |
| **待验收** | **执行完成但证据未核，或验收条件只达成一部分** | → 已通过 / 未通过 |
| 已通过 | **证据充分且已独立核对** | — |
| 未通过 | 验收不达标 | → 进行中（返工）/ 待决策 |
| 已接受为已知限制 | 经决定不再修 | — |

> **铁律**：报告中写"已完成"但无对应证据 → **只能记 `待验收`**。

### 1.2 三层证据（不得混用）

| 层 | 判定条件 | 能否关闭"发布/真实行为"类条件 |
|---|---|---|
| ① 代码已改 | 源码哈希 + diff | 否 |
| ② 测试通过 | 指定用例在 node 环境通过（**须有本次执行输出**） | 否（除非条件本身即测试类） |
| ③ 真实环境已验证 | 启动应用 + 真实整合包 + 可复核证据 | **仅 ③ 可以** |

### 1.3 决策五态（本批新增，解决 G-27）

`已登记` → `待决策` → `已答复` → `已实施` → `已验证`，**五态不得互相替代**；判定条件见 `PROJECT-STATISTICS-BASELINE.md` §4.1。
**当前：20 项全部停在"待决策"，已答复/已实施/已验证均为 0。**

### 1.4 统计纪律（本批新增，解决 G-29）

| 规则 | 内容 |
|---|---|
| **S-1** | **所有计数必须从逐行表重算**，禁止沿用任何汇总数字 |
| **S-2** | 每个数字必须注明**来源文件 + 章节 + 统计规则** |
| **S-3** | 无法复核的数字标 `未核实` 并保留原值，**不得**用估算替代 |
| **S-4** | 发现历史计数错误时：**不改原报告**，在新文档登记并给出正确值（如 G-29：23 而非 22） |

### 1.5 授权等级

| 级别 | 允许动作 |
|---|---|
| A0 | 只读核查 |
| A1 | 写 `docs/` 计划与报告 |
| A2 | 改源码 + 测试 |
| A3 | 运行测试 / typecheck / lint |
| A4 | 启动应用 / 真实整合包 |
| A5 | 构建 / 打包 / 安装 / 发布 |

### 1.6 每批门禁（7 项）

保护边界核对 → 改动清单 + 前后哈希 → 任务验收证据（分层标注）→ 回归结果 → 既有测试未被删/跳/放宽 → 回滚命令可执行 → 计划与 CHANGELOG 同步。

## 2. 任务 1：T-10 ⑤ 回退路径用例

### 2.1 先纠正一个前提（本批关键发现 G-34）

`stripLiteralsAndComments` 只在 **acorn 词法器抛错**时回退；而 `tokenizer` 只做**词法**分析，
`function ( {` 这类**语法**错误它**不会抛**。因此 `hookBlacklist.test.ts:124` 那条题为
"语法非法的源码回退到字符扫描"的用例，**实际走的是主路径**（它只断言 `not.toThrow()`，主路径也能通过）。

→ 要真正进入回退路径，输入必须含**词法**错误（本批用"末尾未闭合字符串"）。

### 2.2 探针实测（先看真实输出，再写断言）

| 输入 | 结果 |
|---|---|
| `var re = /[/*]/; require('fs'); var s = 'abc`（**未闭合**） | **`[]`** ← 回退路径丢掉 require |
| `var re = /[/*]/; require('fs'); var s = 'abc'`（闭合） | `['require']` ← 主路径正常 |
| 嵌套模板 + 未闭合字符串 | `['require','fs']` |
| 嵌套模板（闭合） | `['require']` |
| `module.exports = function ( { return 1`（既有用例输入） | `[]`（本就没有禁用词） |

→ 用"**同一段文本、只差一个引号**"的对照，差异只能由"走了不同路径"解释——这就是路径证据。

### 2.3 新增文件与用例

| 文件 | 状态 | 用例 |
|---|---|---|
| `tests/plugins/hookFallback.test.ts` | **新增**（SHA-256 `861c8d899615e7237f5f…`） | 2 例：①RV1-005 回退路径丢失 require（与主路径对照）；②RV1-006 回退路径不产生假阴性但多判 `fs`（主路径无此问题） |

**测试目的**：在不修字符扫描的前提下，把"回退路径的真实行为"固定下来。
**为什么断言的是当前行为**：回退只在源码过不了词法分析时发生，这类源码也无法被执行；
黑名单是第二道防线（真正边界是 `vm`+`codeGeneration`），所以该缺陷只影响诊断质量。
若将来改进扫描器，这 2 例会变红——**那是有意的**，改动必须被显式确认，不允许"顺手改绿"。

### 3.1 T10-A｜BH2-004：`FieldKind` 与 `'list'`

**① `FieldKind` 实际定义（`src/shared/types.ts:12-25`）**

```ts
/** 渲染控件形态：11 种之一，UI 只按 kind 分支，不按配方类型分支 */
export type FieldKind =
  | 'item' | 'fluid' | 'tag' | 'registry' | 'number' | 'boolean'
  | 'choice' | 'text' | 'struct' | 'nbt' | 'blockstate' | 'unknown'
```

- **共 12 个成员，无 `'list'`**。
- ⚠️ 注释写"11 种之一"，实际枚举 12 个 → **注释数字过时**（登记为 D-23b，非缺陷、仅文档瑕疵）。

**② `primitives.ts` 里的 `'list'` 属于另一个类型**

| 位置 | 内容 | 归属 |
|---|---|---|
| `primitives.ts:14-25` | `export type PrimitiveKind = 'scalar' \| 'reference' \| 'reference_amount' \| 'list' \| 'struct' \| 'nested' \| 'modifier'` | **`PrimitiveKind`**（不是 `FieldKind`） |
| `primitives.ts:128-129` | `export function classifyPrimitive(field) { … if (field.isArray) return 'list' … }` | 同上 |
| `primitives.ts:196` | `registryKindOf(...): FieldKind` | 这是**唯一**返回 `FieldKind` 的导出函数，不含数组分支 |

**③ `kindForField` 的实际实现（`src/main/schema/infer.ts:116-137`）**

```ts
function kindForField(f: InducedField): FieldKind {
  const g = levelOf(f)
  const primitive = classifyPrimitive(g)
  if (primitive === 'nested') return 'struct'
  if (primitive === 'blockstate') return 'blockstate'
  if (primitive === 'nbt') return 'nbt'
  if (primitive === 'reference' || primitive === 'reference_amount') return registryKindOf(...)
  if (primitive === 'struct') return 'struct'
  // ★ 注意：没有 `if (primitive === 'list')` 分支
  const c = g.shapeCounts
  if (c.string + c.number + c.boolean > 0 && c.object + c.array > 0) return 'unknown'
  if (c.boolean > 0 && c.number + c.string === 0) return 'boolean'
  if (c.number > 0) return 'number'
  if (c.string > 0) { … 'choice' | 'text' }
  return c.object > 0 ? 'struct' : 'unknown'   // ← 纯数组字段落到这里
}
```

**关键推理（静态，可确认）**
1. `classifyPrimitive` 对纯数组字段返回 `'list'`；
2. `kindForField` **没有** `'list'` 分支 → 继续走下方 shapeCounts 判断；
3. 纯数组：`string/number/boolean === 0`、`object === 0`、`array > 0` → 前 5 个 if 均不命中 → 落到最后一行 → `c.object > 0` 为假 → 返回 **`'unknown'`**。
4. 数组性由另一字段承载：`infer.ts:148` `multiple: f.isArray`。

### 3.3 T10-C｜RV1-005：正则字面量被当作注释

**① 原始问题（`BUG-HUNT-02-RV1-INDEPENDENT-REVIEW.md:235`）**

> `stripLiteralsAndComments` 不识别正则字面量；`/[/*]/` 会吞掉后续代码 → 黑名单漏检（**不构成能力提升**）

**② 当前实现：两条路径**

| 路径 | 位置 | 关键行为 |
|---|---|---|
| **主路径（acorn 词法器）** | `hookSandbox.ts:166-186` `stripWithTokenizer` | `tokenizer(source, {ecmaVersion:'latest',…})`；**显式丢弃** `tokTypes.string`(:178)、**`tokTypes.regexp`(:179)**、`tokTypes.template`(:180) → 正则字面量被整体跳过，**不会再被当成注释** |
| **回退路径（字符扫描）** | `hookSandbox.ts:190-193` `stripLiteralsAndComments` 的 `catch` → `stripWithScanner`（实现约 `:80-152`） | 只处理 `//`、`/* */`、`'…'`、`"…"`、`` `…` ``；**grep 确认无任何正则分支** |

**③ 源码自带的说明（强证据，`hookSandbox.ts:157-165`）**

```
 * RV1-005 / RV1-006：字符扫描无法区分「正则字面量」与「除号」，也无法正确处理嵌套模板。
 * 例如 `var re = /[/*]/` 会被误判成块注释开始，把后面真实的 `require('fs')` 一起吞掉；
 * `a${`b${c}`}` 内层的 `}` 会被当成插值结束。词法器天然知道上下文，这两个问题一起消失。
```

**④ 静态可确认 vs 需运行时**

| 命题 | 可确认性 |
|---|---|
| 主路径丢弃 regexp token | ✅ **静态可确认**（`:179`） |
| 回退路径无正则分支 | ✅ **静态可确认**（grep 无命中） |
| 回退路径何时可达 | ✅ 静态：**仅当 `tokenizer()` 抛错**（`catch` 分支） |
| 回退路径下 `/[/*]/` 具体会吞掉哪些代码 | ❌ **需构造用例**（本批禁止执行） |
| 该漏检是否带来安全影响 | ⚠️ 需结合沙箱边界判断：真正边界是 `vm.createContext` + `codeGeneration` 限制，黑名单只是第二道防线（见 `hookSandbox` 顶部注释与既有测试）→ **倾向"影响极低"但不由本批定论** |

**⑤ 结论**

- **主路径：已解决**（有源码直接证据 + 注释指名）。
- **回退路径：问题仍存在，但只在"源码本身语法非法"时可达**；非法源码无法通过编译执行 → **不构成逃逸路径**，只影响诊断准确度。
- 状态：**部分确认**（主路径确认修好；回退路径的**实际表现**待用例）。
- 需运行测试：**是**（构造 `var re = /[/*]/; require('fs')` 之类语法非法变体，断言回退路径行为）→ 属 T-10 的 A3/A2 部分，本批不做。

### 3.4 T10-D｜RV1-006：嵌套模板 `}` 误判

**① 原始问题（同上报告 `:236`）**

> 嵌套模板 `` `a${`b}${c}`}` `` 的 `}` 会被误判为插值结束

**② 主路径**

- `stripWithTokenizer` 丢弃 `tokTypes.template`（`:180`），而模板内 `${…}` 的**表达式部分**仍是普通 token → **插值中的调用照样被检查**（注释 `:183-185` 明确写了这一点）。
- 因此主路径**不存在**"`}` 误判"问题。

**③ 回退路径（`hookSandbox.ts:120-145` 附近的模板分支）**

```ts
if (ch === '`') {
  i += 1
  while (i < n) {
    if (source[i] === '\\') { i += 2; continue }
    if (source[i] === '`') { i += 1; break }        // ← 遇到内层反引号即结束外层模板
    if (source[i] === '$' && source[i+1] === '{') {
      const start = i + 2; let depth = 1; i += 2
      while (i < n && depth > 0) { … 统计 { } 深度 … }
      out.push(` ${source.slice(start, i)} `); i += 1; continue
    }
    i += 1
  }
  out.push(' '); continue
}
```

- `${}` 内部**用 depth 计 `{}` 深度** → 处理了"插值里含对象字面量"的情形；
- **但遇到内层反引号会直接 `break` 结束外层模板** → 嵌套模板仍会提前收尾，后续内容被当作代码 → **RV1-006 在回退路径仍成立**。

**④ 结论**

- **主路径：已解决**（template token 丢弃 + 表达式保留）。
- **回退路径：问题仍在**（与 RV1-005 同因：仅在语法非法源码时可达）。
- 状态：**部分确认**；需运行测试：**是**（构造嵌套模板 + 非法语法的组合用例）。
- 直接证据强度：主路径**强**；回退路径**中**（读码可确认结构，但具体吞噬范围需实测）。

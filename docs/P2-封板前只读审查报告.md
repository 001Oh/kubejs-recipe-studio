| `const Ctor = BrowserWindow; new Ctor(...)` | ❌ 不检测 | 同上 |
| `BrowserWindow.fromId(id)` / `getAllWindows()` 复用 | ➖ 不新造窗口，无需守卫 | 不构成绕过 |
| 通过封装函数 `createChildWindow()`（内部仍在某文件 `new BrowserWindow`） | ✅ 检测到该文件 | 但若守卫由调用方而非该文件安装，会**误报失败**（偏严格，不是漏洞） |
| `new  BrowserWindow(`（双空格）/ 注释含 `installNavigationGuards(` | 各自造成漏检/误判 | 见上 |
| 运行时 `window.open()` 派生窗口 | 被 `setWindowOpenHandler` 拒绝（`action:'deny'`） | 但该 handler 只挂在主窗口 webContents 上；若将来新窗口未装 handler，其 `window.open` 不受限 |

**结论**：该测试**具有实际约束力**，新增窗口「按常规写法」几乎必然被发现；但它校验的是「文件里有这个调用」，不是「每个窗口实例都被装上守卫」，存在 3 类绕过（别名构造、双空格/注释、封装函数内的实例归属）。**是否需要补强**：建议未来改为「每个 `new BrowserWindow` 的返回值都必须被 `installNavigationGuards(...)` 消费」的 AST 级检查；本轮不改。

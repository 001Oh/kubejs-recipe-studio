## 0. 一个必须先说清的事实：逻辑大小 ≠ 物理占用

审计报告（§3 表注、§8 第 2 行）指出四份整合包副本"jar 的 `nlink=4` → 与源包共享磁盘块"。本次实测确认：

| 目录 | 逻辑大小 | **独占字节** | 多链接文件数 |
| --- | --- | --- | --- |
| `.cache/pc3-pack-construct` | 1,158.3 MB | **0.0 MB** | 21,372 / 21,375 |
| `.cache/pc7-pack-1112` | 552.6 MB | **0.0 MB** | 1,657 / 1,659 |
| `.cache/pc3-pack-1112` | 552.6 MB | **0.0 MB** | 1,657 / 1,659 |
| `.cache/pc5-pack-1112` | 552.6 MB | **0.0 MB** | 1,657 / 1,658 |

**含义**：这 2,816 MB 只是同一批磁盘块的**多个目录项**。删除其中任何一份都**不会释放一个字节**（块仍被源包与其它副本引用），却会让对应的 E2E 无法复跑（需重新 `cp -al`）。

> 因此本清单把"逻辑大小"与"独占字节"两列并列，**清理决策一律以独占字节为准**。审计报告里"85% 是测试产物"的判断在**文件数**上成立（1,345,753 / 1,711,224 = 78.6%），在**字节**上不成立。
